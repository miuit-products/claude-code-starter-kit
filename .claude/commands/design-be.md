# BE設計ガイドライン

API/バックエンド設計の方針を策定するためのガイドです。

## 必読ドキュメント

1. `CLAUDE.md` - API実装時の必須ルール
2. `docs/TESTING_GUIDE.md` - APIテスト要件

## API実装の順序（必須）

1. 認証・認可チェック → 未認証なら 401
2. 入力値バリデーション（Zod）→ 不正なら 400
3. レート制限 → 超過なら 429
4. 監査ログ記録（必要な場合）
5. データベース処理
6. レスポンス生成

## 出力フォーマット

```markdown
## API設計方針: [エンドポイント名]

### エンドポイント
- Method: GET/POST/PUT/PATCH/DELETE
- Path: /api/[path]
- 認証: 必須/不要
- 権限: [必要な権限]

### リクエスト
- Body/Query パラメータ定義
- バリデーションルール（Zod スキーマ）

### レスポンス
- 成功時: { success: true, data: ... }
- エラー時: 400/401/403/404/429/500

### セキュリティ要件
- [ ] 認証チェック
- [ ] 権限チェック
- [ ] レート制限
- [ ] 監査ログ（必要な場合）

### データベース操作
- 対象テーブル: [テーブル名]
- 操作種別: SELECT/INSERT/UPDATE/DELETE
- RLS 適用: あり/なし

### 必要なテストケース
- [ ] 正常系
- [ ] バリデーション（400）
- [ ] 認証（401）
- [ ] 権限（403）
- [ ] レート制限（429）
```

## セキュリティ必須事項

- 個人情報はログに出力しない
- SQLインジェクション対策
- 監査ログは成功・失敗の両方を記録（必要な場合）
